# Go URL Shortener

Сервис сокращения URL на Go, разработанный в рамках курса Яндекс Практикума. Создаёт короткие ссылки с идентификатором из 10 символов и перенаправляет по ним на исходный адрес.

## Возможности

- Сокращение отдельных ссылок через текстовый и JSON API, пакетная обработка.
- Хранение в памяти, JSONL-файле или PostgreSQL.
- Список ссылок пользователя с идентификацией по подписанной JWT cookie.
- Асинхронное мягкое удаление ссылок с проверкой владельца.
- Поддержка gzip для запросов и ответов, логирование HTTP-запросов через Zap.
- Автоматические миграции PostgreSQL и корректное завершение сервера с ожиданием очереди удаления.

## Быстрый старт

Требуется Go 1.26.5 или новее — версия указана в `go.mod`. PostgreSQL нужен только для режима хранения в базе данных.

В корне проекта выполните:

```sh
go mod download
go run ./cmd/shortener
```

По умолчанию сервер слушает `localhost:8080` и хранит данные в памяти: после перезапуска ссылки теряются.

Для сохранения данных в файл:

```sh
go run ./cmd/shortener -f urls.jsonl
```

Файл создаётся автоматически, существующие записи загружаются при запуске. Если в пути указан каталог, его нужно создать заранее.

Для PostgreSQL сначала создайте базу данных и пользователя, затем передайте строку подключения:

```sh
go run ./cmd/shortener -d "postgres://shortener:password@localhost:5432/shortener?sslmode=disable"
```

Замените параметры подключения на свои. При старте сервис проверяет соединение и применяет встроенные SQL-миграции. При ошибке подключения или миграции запуск прекращается.

## Настройки

Параметры задаются флагами и переменными окружения. Непустые переменные окружения имеют приоритет над соответствующими флагами. Заданные переменные параметров удаления также переопределяют флаги.

| Переменная окружения | Флаг | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `SERVER_ADDRESS` | `-a` | `localhost:8080` | Адрес HTTP-сервера в формате `host:port` |
| `BASE_URL` | `-b` | `http://localhost:8080/` | Базовый URL возвращаемых коротких ссылок |
| `FILE_STORAGE_PATH` | `-f` | Пусто | Путь к JSONL-файлу |
| `DATABASE_DSN` | `-d` | Пусто | Строка подключения к PostgreSQL |
| `LOG_LEVEL` | — | `INFO` | Уровень логирования |
| `SECRET_KEY` | — | Пусто | Ключ подписи JWT cookie |
| `DELETE_BATCH_SIZE` | `-delete-batch-size` | `1000` | Максимальное число ссылок в пакете удаления |
| `DELETE_FLUSH_INTERVAL` | `-delete-flush-interval` | `25ms` | Интервал отправки накопленного пакета на удаление |

Размер пакета и интервал удаления должны быть положительными. Интервал задаётся в формате Go duration, например `25ms` или `1s`.

Хранилище выбирается в порядке **PostgreSQL → файл → память**: при заданном `DATABASE_DSN` файловое хранилище не используется. `BASE_URL` влияет только на возвращаемые ссылки; адрес прослушивания задаётся отдельно.

Пример запуска на другом порту:

```sh
go run ./cmd/shortener -a localhost:9090 -b http://localhost:9090 -f urls.jsonl
```

Перед использованием вне локальной разработки задайте собственный непустой `SECRET_KEY`. Для сохранения действующих cookie между перезапусками используйте один и тот же ключ.

В PowerShell:

```powershell
$env:SECRET_KEY = 'replace-with-a-random-secret'
go run ./cmd/shortener -f urls.jsonl
```

В Bash:

```bash
export SECRET_KEY='replace-with-a-random-secret'
go run ./cmd/shortener -f urls.jsonl
```

## HTTP API

Для текстового POST-запроса используйте `Content-Type: text/plain`, для JSON-запросов — `Content-Type: application/json`.

| Метод | Путь | Назначение | Основные ответы |
| --- | --- | --- | --- |
| `POST` | `/` | Сократить URL из текстового тела | `201` — короткий URL, `409` — URL уже существует |
| `POST` | `/api/shorten` | Сократить URL из JSON | `201` — JSON с полем `result`, `409` — URL уже существует |
| `POST` | `/api/shorten/batch` | Сократить массив URL | `201` — массив результатов, `400` — некорректный пакет |
| `GET` | `/{id}` | Перейти по короткой ссылке | `307` и заголовок `Location`, `410` — удалена, `400` — не найдена |
| `GET` | `/api/user/urls` | Получить активные ссылки пользователя | `200` — массив ссылок, `204` — список пуст |
| `DELETE` | `/api/user/urls` | Передать идентификаторы ссылок на удаление | `202` — запрос принят, `400` — некорректное тело |
| `GET` | `/ping` | Проверить соединение с PostgreSQL | `200` — доступна, `500` — недоступна или не настроена |

При повторном сокращении одного URL одиночные endpoints возвращают `409 Conflict` и ранее созданную короткую ссылку в обычном формате ответа. Пакетный endpoint переиспользует существующие ссылки и возвращает `201`.

### Примеры запросов

Ниже приведены примеры для Bash и `curl`. Для сохранения пользователя используется файл cookie `cookies.txt`.

Сократить ссылку текстовым запросом:

```bash
curl -i -c cookies.txt -b cookies.txt \
  -H 'Content-Type: text/plain' \
  --data 'https://example.com/article' \
  http://localhost:8080/
```

Сократить ссылку через JSON API:

```bash
curl -i -c cookies.txt -b cookies.txt \
  -H 'Content-Type: application/json' \
  --data '{"url":"https://example.com/docs"}' \
  http://localhost:8080/api/shorten
```

Пример тела ответа (идентификатор генерируется случайно):

```json
{"result":"http://localhost:8080/AbCdEf2345"}
```

Пакетное сокращение:

```bash
curl -i -c cookies.txt -b cookies.txt \
  -H 'Content-Type: application/json' \
  --data '[{"correlation_id":"1","original_url":"https://example.com/one"},{"correlation_id":"2","original_url":"https://example.com/two"}]' \
  http://localhost:8080/api/shorten/batch
```

Ответ содержит массив объектов с полями `correlation_id` и `short_url` в порядке исходного запроса.

Получить свои ссылки:

```bash
curl -i -b cookies.txt http://localhost:8080/api/user/urls
```

Каждый объект в ответе содержит `short_url` и `original_url`.

Проверить перенаправление, подставив идентификатор из ответа сервера:

```bash
curl -i http://localhost:8080/AbCdEf2345
```

Удалить ссылки — в теле передаются только идентификаторы, без базового URL:

```bash
curl -i -b cookies.txt -X DELETE \
  -H 'Content-Type: application/json' \
  --data '["AbCdEf2345"]' \
  http://localhost:8080/api/user/urls
```

### Пользователи и удаление

Сервис автоматически выдаёт cookie `userId` с JWT сроком на 3 часа. Если cookie отсутствует, просрочена или некорректна, создаётся новый пользователь. Для работы со своими ссылками нужно передавать ту же cookie в последующих запросах.

Повторное сокращение существующей ссылки добавляет её в список текущего пользователя, но право удаления остаётся у первоначального создателя. Чужие и неизвестные идентификаторы при удалении игнорируются.

Удаление выполняется в фоне четырьмя обработчиками, с накоплением пакетов по размеру или таймеру. Ответ `202 Accepted` означает приём задания в очередь, а не завершение удаления. После обработки ссылка помечается удалённой, исчезает из пользовательских списков и возвращает `410 Gone` при переходе.

Для сжатого тела запроса передавайте `Content-Encoding: gzip`. Для получения сжатого ответа — `Accept-Encoding: gzip`; в `curl` можно использовать `--compressed`.

## Консольный клиент

При запущенном сервере в другом терминале выполните:

```sh
go run ./cmd/client
```

Клиент запрашивает длинный URL, отправляет его на `http://localhost:8080/api/shorten` и выводит статус, заголовки и тело ответа. Адрес сервера зафиксирован в коде клиента.

## Структура проекта

```text
cmd/
  shortener/       запуск HTTP-сервера, маршрутизация и gzip
  client/          интерактивный консольный клиент
internal/
  auth/            JWT, cookie и пользователь в контексте запроса
  config/          флаги и переменные окружения
  handler/         HTTP-обработчики и очередь удаления
  logger/          настройка Zap и логирование запросов
  model/           структуры запросов, ответов и файловых записей
  repository/      хранилища в памяти, файле и PostgreSQL
migrations/        SQL-миграции, встроенные в приложение
.github/workflows/ проверки и автотесты Практикума
```

Каталоги `api`, `pkg`, `internal/service` и `internal/config/db` пока содержат README из исходного шаблона.

## Проверки

Запуск тестов и статического анализа из корня проекта:

```sh
go test ./...
go vet ./...
```

Тесты проверяют HTTP-обработчики, cookie и JWT, настройки, gzip, работу с пользовательскими ссылками, конфликты, пакетное сохранение и удаление.

В GitHub Actions настроены автотесты Практикума и `statictest`. Для pull request проверяется имя ветки `iter<number>` (например, `iter15`); на `main` запускаются все настроенные в workflow проверки инкрементов.
